# Admission recovery qualification — 0.4.5, 2026-10-16

This update addresses the two ways a busy helper could amplify a fault:
checkpoint I/O in the verdict loop and a recovery detector that treated any two
unchanged status reads as a hang. It keeps the existing placement, failover and
source-mapping policies in both sticky and affinity modes.

## Checkpoints stay outside admission

The event loop coalesces mapping changes and complete connection observations.
It forks at most one checkpoint writer, at most once every five seconds. The
child sees an immutable copy of the engine at fork; acknowledging that write
cannot acknowledge changes subsequently made by the parent. A failed fork or
write uses the same rate limit. The two-second worker timeout, pipe reads and
reaping are nonblocking in admission.

The child closes the queue descriptor before doing work, and closes its
inherited health socket and collector pipe. Linux parent-death handling kills
the worker group if the helper dies. Shutdown closes the queue before bounded
worker cancellation/reaping; the final synchronous save cannot hold admission
open. Startup also saves before binding the queue. The on-disk layout and
verification rules are unchanged, so valid same-boot checkpoints still restore.
A crash can lose recent membership updates, which fall back to safe adoption.
Status includes writer PID, successes/failures, last/maximum duration and
netlink receive `ENOBUFS` count.

## Independent recovery

The same executable runs a separate supervisor process. It reads status progress
and `/proc/net/netfilter/nfnetlink_queue` once per second without spawning
commands on each tick. It requires both:

- Five seconds with no observed status progress from the same helper PID.
- At least one packet pending across observations one second apart.

Progress or an empty queue clears pending suspicion. An arbitrarily deep but
short burst does not qualify. A watermark above one would miss a frozen helper
on a quiet network, so one packet is deliberately sufficient. An idle frozen
helper has no pending admission to rescue; the first later packet starts the
one-second pending test against the already-stale heartbeat.

The supervisor rechecks the PID file and executable identity before SIGKILL.
Closing the queue is independent of the lifecycle controller's shell lock,
checkpoint I/O and fact collector. The serialized controller then removes only
owned admission rules and restarts. Normal readiness/configuration/rule checks
remain ten seconds apart. Three stall recoveries within 60 seconds stop retries,
remove admission rules and leave firmware balancing in charge. The RAM
`supervisor-tripped` marker survives supervisor replacement; only explicit
`start` or reboot clears it. A late recovery command cannot undo an explicit
start that already cleared the marker.

## What a user sees

Confirmed connections return before NFQUEUE. A helper freeze delays new,
unconfirmed connection attempts; an established stream does not acquire a new
userspace forwarding dependency. This does not protect an established stream
from losing its WAN or from watchdog routing-policy changes.

Queue-full `FAIL_OPEN` accepts the arrival that could not be enqueued. It leaves
previously queued packets waiting. Closing/destroying the queue can drop those
held packets. Absent-listener bypass accepts later arrivals immediately, but
skips subsequent mangle-table processing, including firmware balance. Removing
the owned jump restores ordinary firmware traversal. The earlier kernel
[fallback qualification](../router-tests/README.md) remains applicable.

A TCP client can retransmit and finish connecting after recovery: often the
visible symptom is a page that takes longer to start loading. Applications with
shorter deadlines can still fail. There is no universal 3/6/12-second SYN retry
schedule. [RFC 6298](https://www.rfc-editor.org/rfc/rfc6298.html) specifies an
initial RTO of one second as a SHOULD and exponential backoff; client policy and
application deadlines affect the observed delay. UDP needs application retries.
Recovery timings below measure queue closure and helper readiness, not an upper
bound on application-visible connect time or a real-time kernel guarantee.

## Relationship to OPNsense

OPNsense's public
[gateway rule generation](https://github.com/opnsense/core/blob/b0504c9cf0eb121d17fb19c9e9a981a0ba2a0792/src/opnsense/mvc/app/library/OPNsense/Firewall/Plugin.php#L150-L166)
uses pf's `sticky-address`; its
[sticky-connection settings](https://docs.opnsense.org/manual/firewall_settings.html#sticky-connections)
describe source mappings retained by active states. That remains the reference
for our default mapping behavior. The userspace admission recovery described
here is specific to Linux NFQUEUE; it is not an OPNsense watchdog algorithm or
a claim to reproduce pf internals. No OPNsense code was copied for this update.

## Validation

The host suites cover the engine and checkpoints, async worker, mapping-change
coalescing, in-flight snapshot revisions, retry rate limiting, progress/PID
changes, short queue bursts, single-packet freezes, idle freezes and the sliding
restart budget. The lifecycle regressions cover the trip marker, broken config,
explicit restart and late recovery. Sanitizers exercise both the engine/cache
and supervisor/scheduler paths.

The opt-in router test uses the production executable with an isolated queue,
runtime and loopback scope. Only its controller copy redirects the hook to
OUTPUT; a read-only shim supplies the balance anchor for ownership checks.
The real helper, supervisor, verdicts, process signals and kernel queue are used.
A router-local cleanup guard is armed before linking the test chain. Real WAN
health, household admission, routing policy, pins and hooks are not faulted.

The driver and reproduction commands are in
[router test instructions](../router-tests/README.md#admission-stalls-and-blocked-checkpoints).


### Measured fault results (final packaged executable)

The normal production executable passed a 90-second blocked-writer pressure
run, followed by a 30-second run and the complete fault matrix. The longer run
completed 14976 echo requests (maximum 5.745 ms), with 17 writer timeouts, no receive
overruns and no false helper restart. Short successful loopback flows can remain
confirmed between batches, so the admission counter is lower than the request
count; this is not a benchmark of new connections per second.

| Measurement | Samples | Minimum | Median | p95 / maximum |
| --- | --- | --- | --- | --- |
| Freeze to queue closure | 12 | 4.439 s | 5.316 s | 5.825 s |
| Freeze to full controller activation | 12 | 5.678 s | 6.642 s | 7.123 s |
| Fresh echo after SIGKILL (request RTT) | 12 | 0.145 ms | 0.157 ms | 0.182 ms |

Timing from host-driven signals includes SSH/observation latency. Sampling
phase explains queue closure below five seconds from SIGSTOP: the last observed
status change can precede the freeze. Full activation requires both the new
queue and the reinstalled admission jump, rather than queue binding alone.
With twelve samples, the nearest-rank p95 is the maximum; this small sample is
not a tail-latency guarantee for all routers or workloads.

A helper frozen for seven idle seconds was left alone with an empty queue.
One subsequent packet triggered queue closure in 1.703 seconds. Killing the
helper while a checkpoint writer was blocked closed the queue within the
48.9 ms host observation window; a fresh echo took 0.143 ms and no worker kept
running. Three stalls within a minute removed the admission rules, blocked
further automatic reconciliation, and allowed an explicit `start` to restore
service. A confirmed echo flow spanning the complete matrix delivered all
3,771 packets, with maximum RTT 0.935 ms.

Before/after checks preserved production helper/watchdog PIDs, all firewall
rules (ignoring counters), routing rules, GUI pins and startup-hook bytes.
Only the fixture's exact loopback connections were deleted. The tests caused
no deliberate household WAN transition, reboot or blanket conntrack flush.


The separate loopback lifecycle regression also passed with the 0.4.5 test
build: 16 never-confirmed drops cleaned up, a packet held for four seconds kept
its mapping until release, and 360 admissions continued through a 1.5-second
fact-collector delay. The 72 measured echo round trips in that delayed-collector
case had maximum RTT 0.235 ms. Collector timeouts preserved admission and made
health unknown when facts became stale; killing the helper leaked neither the
queue nor a running collector.


The LAN-bound Mini adoption matrix passed in both `sticky` and `affinity` modes.
Each kept two existing HTTPS sessions on different WANs while sixteen parallel
new HTTPS connections used one source mapping. A private helper restart restored
that mapping, and two further HTTPS connections followed it. The original
connection identities, WAN marks and NAT addresses remained unchanged. The
health-consumer suite passed 633 checks. Production services stayed running;
cleanup restored the exact GUI pin, routing rules, firewall rules and hooks.


An additional independent-enforcement test held the private controller's file
lock while freezing its helper with one packet pending. The supervisor closed
the queue in 5.650 seconds, before the lock was released; a fresh request then
completed in 0.156 ms. Releasing the lock allowed the controller to finish normal
reactivation. The confirmed flow lost no packets.


### Guarded production upgrade

The supported `install.sh --upgrade` installed 0.4.5 on the live router with an
independent 240-second rollback guard. The controller restored same-boot source
mappings, retained sticky mode and the existing configuration, and reconnected
to WAN Watchdog. The upgrade preserved GUI pins, firewall rules, routing rules,
startup-hook bytes and the running watchdog PID. The rollback guard was disarmed
after successful checks; its saved previous installation remains recoverable.

A subsequent five-minute production soak (31 samples over 304.3 seconds) kept
the helper and independent supervisor PIDs stable, both WANs eligible, and all
queue-drop, receive-overrun, checkpoint-failure and collector-failure counts at
zero. Checkpoints completed throughout. Eight additional LAN-bound Mini checks
passed: four HTTPS, two DNS and two QUIC version-negotiation requests.

This is bounded qualification on one RT-AX88U / Merlin 3004.388.12_2 / Linux
4.1.51 system. It does not establish overnight reliability, worst-case latency
under kernel/resource stalls, maximum connection-arrival rate or support for
other hardware. No deliberate production helper freeze, WAN outage, reboot,
firmware upgrade or aggregate saturation test was performed for this update.
